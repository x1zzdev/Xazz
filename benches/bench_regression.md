# 벤치마크 회귀 판정

`run_readme_benchmark.py`가 기록한 pandas와 xazz 파이프라인 지연의 비율을
커밋된 기준선과 비교한다. `pandas.latency_ms / xazz.latency_ms`가 기준선 대비
35% 넘게 낮아지면 실패한다. 정확히 허용 경계인 값은 통과한다.

```sh
python benches/bench_regression.py \
  --current bench-current.json \
  --baseline benches/bench_regression_baseline.json
python -m unittest discover -s benches -p "test_bench_regression.py" -v
```

## 입력 계약

- 양쪽 JSON은 하나 이상의 스케일을 포함하는 객체여야 한다. 스케일 이름의 집합이
  정확히 일치해야 한다. 기준선이 `small`만 포함하면 `--quick` 결과를 사용한다.
  어느 한쪽에만 있는 스케일은 비교 누락으로 처리해 실패한다.
- 선택적인 최상위 `provenance` 객체는 호스트 메타데이터다. 성능 스케일로 비교하지 않는다.
- 각 스케일의 `rows`는 양의 정수여야 하며 현재 측정과 기준선이 같아야 한다.
- `pandas`와 `xazz`의 `latency_ms` 및 `runs` 안의 모든 지연은 유한한 양수 JSON
  숫자여야 한다. 문자열, 불리언, null, 0, 음수, NaN과 무한대는 허용하지 않는다.
- 각 엔진의 `runs`에는 워밍업을 제외한 3회 측정이 필요하다. 요약 `latency_ms`는
  원시 측정 중앙값을 소수점 첫째 자리로 반올림한 값과 같아야 한다.
- xazz의 모든 원시 측정은 `fallback_to_wallclock: false`여야 한다. 타이밍 마커가
  없어 프로세스 전체 시간으로 대체한 결과나 측정 방식이 불명확한 결과는
  파이프라인 지연과 비교할 수 없으므로 실패한다.
- `--tol`은 0 이상 1 미만의 유한한 수다. JSON 중복 키, 잘못된 JSON, 읽을 수 없는
  파일도 실패하며 해당 경로를 진단에 출력한다.

모든 입력을 검사한 뒤 성능을 판정한다. 입력 오류 또는 회귀는 종료 코드 1,
유효한 모든 스케일 통과는 종료 코드 0이다. 잘못된 입력이 있으면 `회귀 없음`을
출력하지 않는다. 비교 경계에는 십진 유리수 연산을 사용해 부동소수점 반올림으로
정확한 경계값을 잘못 거부하지 않는다.

## 검증 범위

비교기 계약 테스트는 외부 Python 패키지와 실행 엔진 없이 실행할 수 있다.
일반 PR CI와 벤치마크 워크플로에 테스트를 연결하는 변경은 로컬에서 준비했으나,
현재 인증의 workflow 권한 부족으로 원격 반영되지 않았다. 이 PR에는 비교기·테스트·
문서를 포함하며 CI 연결은 후속 반영이 필요하다. 기존 벤치마크 워크플로는 릴리스
실행 엔진을 빌드하고 합성 small 데이터를 측정한다. 단위 테스트 통과는 측정 데이터와 판정의 계약을 확인한 결과이며, 실제 성능
회귀가 없음을 입증하는 결과가 아니다. 성능 판정에는 해당 워크플로의 실측 결과가 필요하다.

테스트는 정상 기준선, 허용 경계, 기준 미달, 잘못된 입력, 부분 스케일 누락, 행 수
불일치, wall-clock 대체, CLI 종료 코드를 확인한다. 비율 판정은 별도의 정수 교차곱
기준으로 2,401개 조합을 검사한다. 행 수 일치 검사는 데이터 내용의 동일성을 보장하지
않으므로 데이터 생성 방법을 바꿀 때는 기준선의 비교 가능성도 따로 검토해야 한다.
