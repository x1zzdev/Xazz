# 공공데이터 개방 현장 사례 — 가명정보 통계

지방자치단체/공공기관의 복지 수급 통계 개방을 재현한 `.xzz` 프로젝트다.
"시군구별 수급 실태를 개방하라"는 요청이 **어떻게 개인정보보호법 위반이 되는지**,
그리고 **어떻게 가명정보 통계로 안전하게 개방하는지**를 한 쌍으로 보여준다.

> ⚠️ 데이터는 고정 시드로 생성한 **합성 데이터**다. 실제 주민·수급자 정보는 한 건도
> 포함하지 않는다. 프레이밍은 [`docs/design/field-validation.md`](../../../docs/design/field-validation.md) 참고.

| 파일 | 내용 |
|---|---|
| `generate_welfare.py` | `data/welfare.csv`: 30,000건 합성 복지 수급 데이터 (시드 42) |
| `welfare_blocked.xzz` | 규제 위반 예제 — 실행 전에 차단된다 |
| `welfare_safe.xzz` | 가명정보 통계로 안전하게 개방하는 예제 — 통과 |
| `xazz.policy.json` | 공공부문 정책 팩(자동 로드) — 공공데이터법·가명정보 가이드라인 |

## 실행

```bash
cd examples/field_cases/public_sector_stats
python3 generate_welfare.py         # data/welfare.csv (시드 42)
xazz policy welfare_blocked.xzz     # 위반 리포트
xazz policy welfare_safe.xzz        # 통과 (exit 0)
xazz run    welfare_blocked.xzz     # 차단 확인 (exit 1)
xazz run    welfare_safe.xzz        # 실행 → 시도별/연령대별 집계
```

## 무엇을 보여주는가

**위반 예제(`welfare_blocked.xzz`)**:

| 규칙 | 위반 내용 | 근거 |
|---|---|---|
| XZP001 | 수급자 성명이 결과로 그대로 나감 | 개인정보 보호법 제24조 · 공공데이터법 제17조 |
| XZP002 | 개인별 수급 유형이 행 단위로 노출 | 개인정보 보호법 제23조 |
| XZP003 | 나이+성별+동+세대원수 결합 재식별 | 개인정보 보호법 제28조의5 |
| XZP004 | 수급 유형별 집계에 DP 미적용 | 가명정보 처리 가이드라인 |

**안전 예제(`welfare_safe.xzz`)** — 개인 식별 없이 같은 통계를 개방한다:

- 시도별 수급 건수·급여 총액 + 차등 프라이버시
- 연령대별(`age_band` 문자열) 수급 건수·평균 급여 + 차등 프라이버시
- DP 노이즈는 급여액 집계 컬럼에만 더해진다 (문자열 그룹 키는 그대로)

결과 예시(연령대별 수급 건수, 시드 42): 0s~90s 각 구간에 노이즈가 더해진 건수/평균이
나오며, DP 예산은 실행을 넘어 테넌트 원장에 누적된다.

## 이 사례가 시사하는 것

- **"개방"은 곧 "식별 불가"여야 한다.** 가명정보 통계는 소집단 재식별 위험을 DP로
  완화해야 한다.
- 정책 팩은 조항별 `source_ref`를 함께 내보내 감사 증적으로 쓸 수 있다.
- 같은 DSL로 통계 집계와 프라이버시 보호가 한 파이프라인에서 완결된다.

## 한국어 요약

복지 수급 통계 개방을 소재로, "개방 요청이 왜 개인정보보호법 위반이 되는가"와
"어떻게 가명정보 통계로 안전하게 개방하는가"를 대조하는 예제다. 합성 데이터만 쓴다.
`welfare_blocked.xzz` 는 실행 전에 차단되고, `welfare_safe.xzz` 는 시도·연령대 단위로
집계하고 급여액 집계에 차등 프라이버시를 건다.
