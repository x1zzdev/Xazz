# 실무 컨택 제안서 · 이메일 템플릿

상태: 문서 v1 · 관련: [`field-validation.md`](field-validation.md) (Tier 2)

> Tier 2("도전·대기")의 근거를 만들기 위한 컨택 템플릿 모음이다. 원칙은 **과장하지
> 않기**: 현재 상태(합성 PoC/로컬 실행)를 정확히 밝히고, 상대가 검증할 수 있는
> 링크를 준다. 응답이 없으면 "제안함"까지만 기록한다.

## 공통 원칙

1. **상태를 먼저 밝힌다** — "합성 데이터 PoC / 오픈소스, pre-1.0".
2. **요청을 한 문장으로** — 피드백 / 파일럿 검토 / 데이터 스키마 검증 중 하나.
3. **검증 링크** — 저장소, 재현 스크립트, 데모 영상.
4. **부담을 낮춘다** — 30분 미팅 또는 비공개 피드백.
5. **개인정보 금지** — 상대 데이터·개인정보를 요청하지 않는다. 필요 시 공개 문서 기반.
6. **비공개 유지** — 컨택 내용은 대외 자료에 익명 요약으로만.

## 1. 금융권 데이터/리스크팀 (FDS PoC)

**제목**: `[제안] 이상거래 집계 파이프라인의 실행 전 개인정보 게이트 — PoC 검토 요청`

```
안녕하세요, {담당자}님.

Xazz 오픈소스 프로젝트의 {이름}입니다. 이상거래탐지(FDS) 파이프라인에서
"개인신용정보가 결과로 새는 코드"를 실행 전에 막는 접근을 만들고 있습니다.

현재 상태(정직하게): 합성 거래 데이터로 로컬에서 동작하는 PoC까지 완료했습니다.
실제 기관 데이터나 도입은 없습니다.

보여드릴 수 있는 것
- 합성 카드 거래 20,000건으로, 순진한 집계 코드가 실행 전에 차단되는 예제
- 같은 질문을 식별자 없이 안전하게 답하는 예제 (업종/연령대 단위 + 차등 프라이버시)
- 차단 사유가 신용정보법 조항까지 추적되는 감사 리포트

재현: {저장소 URL}/tree/main/examples/field_cases/finance_fds
데모 영상: {URL}

요청: 30분 온라인 미팅에서 이 접근이 현장 규제 검토에 쓸모가 있는지 의견을 듣고
싶습니다. 부담되시면 비공개 피드백만 주셔도 감사하겠습니다.

감사합니다.
{서명}
```

## 2. 공공기관 / 지자체 데이터 담당

**제목**: `[제안] 가명정보 통계 개방 시 소집단 재식별 완화 — 검토 요청`

```
안녕하세요, {담당자}님.

{기관}의 공공데이터 개방 업무에 참고가 될 만한 오픈소스 도구를 만들어 공유드립니다.

현재 상태: 합성 복지 데이터로 로컬 PoC까지 완료했습니다(실제 행정 데이터 아님).

보여드릴 수 있는 것
- "시군구별 수급 실태 개방"이 왜 개인정보보호법 위반이 되는지 (실행 전 차단)
- 같은 통계를 가명정보로 안전하게 개방하는 예제 (지역/연령대 집계 + 차등 프라이버시)
- 위반 사유가 개인정보 보호법·공공데이터법 조항까지 추적됨

재현: {저장소 URL}/tree/main/examples/field_cases/public_sector_stats

요청: 개방 통계 작성 실무에서 이런 사전 점검이 유용할지 의견을 듣고 싶습니다.
```

## 4. PoC 제안서 (1페이지 구조)

```markdown
# Xazz PoC 제안 — {기관/팀} {업무}

## 1. 문제
{현장 요청} 이 왜 {규제} 위반/리스크가 되는가 (한 문단).

## 2. 제안 (범위)
- 대상 파이프라인: {설명}
- 게이트: 실행 전 정적 검사(개인정보/시크릿) + 집계 DP + 감사 로그
- 비범위: {명시 — 예: 운영 배포, 데이터 이관}

## 3. 현재 상태 (정직)
- 합성 데이터 로컬 PoC 완료: {재현 링크}
- 실제 데이터/도입: 없음

## 4. 검증 방법
- {담당자}가 {스키마/공개문서} 기반으로 예제를 확인
- 산출물: 위반 리포트(JSON), 감사 체인 검증

## 5. 요청
- 30분 검토 미팅 / 스키마 피드백

## 6. 데이터 취급
- 실제 개인정보는 요청하지 않음. 공개 문서 기반 재현 또는 합성 대체.
```

두고, 대외 자료에는 익명화한 요약만 넣는다.
