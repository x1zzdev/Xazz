# 협업 규칙 — 이슈 운영과 한국어 문체

팀이 이슈를 만들고 리뷰할 때 지키는 규칙입니다. 트래킹이 서로 어긋나거나
문장이 AI 초안처럼 읽히는 일을 줄이는 게 목적입니다.

## 1. 이슈와 트래킹

1. 트래킹 이슈 하나가 워크스트림 하나를 맡습니다. 하위 이슈 목록과 실제
   상태(open/closed)를 항상 맞춥니다.
2. 실행 순서에는 열린 이슈만 넣습니다. 닫힌 항목은 체크리스트에 `[x]`로
   남겨 이력으로만 둡니다.
3. 의존성 방향을 양쪽에서 맞춥니다. A에 `후속: B`가 있으면 B에는
   `선행: A`가 있어야 합니다. 닫힌 이슈를 후속이나 선행으로 걸지 않습니다.
4. 코드, 필드, 경로, 워크스트림 코드는 기억이 아니라 실제 소스에서 확인해
   인용합니다.
   - 워크스트림 코드는 `docs/ROADMAP.md`의 트랙(A~G)을 따릅니다. 없는 코드를
     만들지 않습니다.
   - 정책 팩 필드는 `rule_source_refs`처럼 실제 이름을 씁니다.
   - 이미 있는 구조(`slm: SlmStatus` 등)를 중복 정의하지 않고 재사용합니다.
5. 모든 이슈에 트랙 라벨(`scale:*`) 하나와 성격 라벨(`bug`,
   `enhancement`, `security`, `documentation` 중 필요한 것)을 붙입니다.
6. 담당자는 한 명으로 둡니다. 팀 간 의존은 이슈 번호로 명시합니다.
7. 부모 이슈와 자식 이슈가 겹치면 관계와 남은 범위를 본문에 적습니다.
   예: 전체 acceptance 이슈와 그중 Windows 재시도 이슈를 나눠 적기.
8. 이슈를 수정하기 전에 현재 본문을 다시 읽고, 바꾼 뒤 전후를 확인합니다.
   남의 이슈를 고치면 무엇을 왜 바꿨는지 남깁니다.

## 2. 이슈 본문 템플릿

    상위 트래킹: #NNN

    <배경 — 지금 상태와 왜 필요한지>

    할 일
    - <구체적인 변경>

    완료 기준
    - <검증 가능한 결과>

    의존성
    - 선행/후속: #NNN

    평가 기준: <대회/프로젝트 평가 항목>

- 완료 기준은 테스트 명령, 문서 산출물, 측정 수치처럼 확인 가능한 형태로
  씁니다.
- 배경에는 근거가 되는 파일 경로나 현재 동작을 적습니다.

## 3. 한국어 문체 (AI 티 줄이기)

출처는 문서 끝에 적었습니다. 한 번 나온 표현을 기계적으로 지우는 게 아니라,
여러 신호가 겹쳐 문장이 딱딱해질 때 고칩니다.

1. 번역투를 걷어냅니다: `~를 통해`, `~에 대해`, `~에 있어서`, `~에 의해`,
   `가지고 있다`, 이중 피동 `~되어진다`.
2. AI 관용구를 피합니다: `결론적으로`, `시사하는 바가 크다`,
   `주목할 만하다`, `혁신적인`, `최적화된`.
3. 문두 접속사를 남발하지 않습니다: `또한`, `따라서`, `즉`, `나아가`.
   관계가 분명하면 접속사 없이 잇습니다.
4. 명사화를 줄입니다. `~성`, `~화`, `가능합니다`, `제공됩니다`보다 주체와
   동사로 씁니다.
   - 나쁨: "자동화 기능 제공이 가능합니다."
   - 좋음: "자동으로 처리해 시간을 줄입니다."
5. 형식명사와 당위 표현을 아낍니다: `것이다`, `점`, `수`, `바`,
   `~할 필요가 있다`.
6. 문장 길이와 종결어미를 고르게 만들지 않습니다. 같은 `~할 수 있습니다`가
   반복되면 문장을 합치거나 자릅니다.
7. 헤징을 겹치지 않습니다. `~할 수 있을 것으로 보인다` 대신 확인한 범위만
   적습니다.
8. 서식을 남발하지 않습니다. 굵은 글씨, 대시(`—`), 이모지, 불릿은 꼭 필요한
   자리에만 씁니다.
9. 사실, 수치, 고유명사, 직접 인용은 그대로 둡니다. 없는 근거를 새로 만들지
   않습니다.
10. 말투를 하나로 유지합니다. "물론입니다, 아래와 같이 정리해 드립니다" 같은
    챗봇식 전개는 쓰지 않습니다.
11. 이슈나 보고서처럼 형식이 정해진 글은 형식 일관성이 문체보다 우선합니다.
    패턴이 한 번 보인다고 AI가 썼다고 단정하지 않습니다.

## 4. 리뷰 점검표

1. 실행 순서에 닫힌 이슈가 있는가.
2. 의존성 방향이 양쪽에서 맞는가.
3. 인용한 코드, 필드, 경로, 워크스트림 코드가 실제로 있는가.
4. 트랙 라벨과 성격 라벨이 다 붙었는가.
5. 완료 기준이 검증 가능한가.
6. 번역투, AI 관용구, 서식 남발이 반복되는가.
