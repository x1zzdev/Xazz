# #166 Windows 후속 수정과 회귀 검증

2026-10-06, PR #285의 미커밋 작업 트리에서 추가 검증을 진행했다. [최초 CPU 실측 기록](benchmark-scale-166-windows-2026-10-06.md)의 200,371,584행 결과와 원시 근거는 그대로 보존했다. 이번 기록은 CSV 저장 실패, 서버 감사로그 경합, 작은 입력의 전체 셀 대조, CI 연결에 관한 것이다. 커밋·푸시는 하지 않았다.

## 수정한 동작

`xazz run ... --output ...`은 계산이 성공해도 지정한 CSV를 저장하지 못하면 실패 종료한다. 기존에는 저장 실패를 경고로 출력하고 성공 종료했다. 이제 원래 경로·OS 오류를 전파하고 최종 결과·타이밍·저장 완료 마커를 내보내지 않는다. 결과 JSON 직렬화 실패도 빈 배열로 대체하지 않는다. 계산 시간의 측정 종료 지점은 유지했다. 출력 파일의 원자적 교체나 쓰기 도중 실패 시 부분 파일 삭제까지 추가한 변경은 아니다.

감사로그 읽기는 쓰기의 배타적 잠금과 같은 파일 범위에 공유 잠금을 획득한 뒤, 그 핸들에서 전체 내용을 읽는다. 파일 부재만 빈 로그로 처리하고 열기·잠금·읽기·파싱 오류는 유지한다. 감사 체인의 실제 해시 손상은 `false`, 읽기 실패는 오류로 구분하며 서버는 후자를 HTTP 500으로 반환한다. 병렬 테스트는 프로세스별 임시 디렉터리의 같은 체인을 공유한다. 운영 경로는 `audit_log/audit.jsonl`로 유지했다. 기존 로컬 서버 로그의 크기 12,907바이트와 수정 시각 10:05 KST는 추가 검사 뒤에도 같았다.

새 전체 셀 대조기는 실제 벤치마크 템플릿을 각 단계 끝에서 잘라 실행한다. 고정 입력 3개 × on/off × P2/P3/P4/P7, 총 24회가 모두 성공해야 통과한다. pandas와 실제 실행 파일을 각각 표준 라이브러리로 계산한 정답과 대조한다.

- 12행 입력: 결측값, 필터 경계 10·50·120, 합계·평균·결측 대체 후 계수.
- 2행 입력: 문자열 `NA`·`NULL`을 결측으로 바꾸지 않는지 확인.
- 78행 입력: 측정소 12개, 소수 값, 경계 순위에 동점 없는 평균·계수. P2/P3/P4/P7 행 수는 78/12/10/5이며 상위 10개·5개 제한이 실제로 적용된다.

열 이름·순서·자료형, 모든 셀, 집계 행 수, 내림차순, 수집 모드·API 완료 마커와 타이밍 마커를 검사한다. 수치 허용 오차는 상대·절대 각각 `1e-12`이고 NaN·무한대는 거부한다. 순서가 정의되지 않은 집계와 동점 행은 순서 자체를 정답으로 고정하지 않는다. 실행 파일 누락, 비정상 종료, 제한시간 초과, 결과 누락은 제외하지 않고 실패로 남긴다. 프로세스 측정·정리는 기존 측정기를 재사용한다.

CI에는 Python 3.12와 버전을 고정한 `benches/requirements.txt`를 연결했다. Python 회귀 검사는 Linux·Windows에서, 실제 셀 대조는 기존 Rust 테스트 빌드 다음에 Linux·Windows·macOS에서 실행하도록 설정했다. 성공·실패 로그와 JSON은 실행 뒤 아티팩트로 보관한다. YAML 파싱·단계 연결은 로컬에서 확인했으며 새 워크플로의 원격 실행은 아직 하지 않았다.

## 검증 결과와 실패 기록

| 검사 | 최종 결과 |
| --- | --- |
| Rust 전체 워크스페이스 병렬 검사 | 677개 통과, 실패·제외 0개 |
| 서버 검사 | 위 검사에 포함된 118개 모두 통과; 앞서 실패했던 두 검사 포함 |
| 포맷·Clippy | 통과, 경고를 오류로 처리 |
| Python 전체 검사 | 69개 중 68개 통과, 실패 0개, 기존 POSIX 전용 검사 1개 제외 |
| 실제 debug 실행 파일의 전체 셀 대조 | 필수 24회 모두 통과 |
| CLI → runner → exec 출력 오류 전파 | 일반·JSON 출력 각각 정상 경로·없는 상위 경로·디렉터리 대상, 총 6개 기대 결과 일치 |

GNU Windows의 큰 debug 실행 파일 문제에 맞춰 `CARGO_PROFILE_DEV_DEBUG=0`으로 디버그 정보만 제외했다. 테스트와 debug assertion을 유지했고 전체 Rust 검사는 기본 병렬 설정으로 수행했다. 이번 통과를 직렬 실행 결과로 대신하지 않았다. 의존성을 바꾸지 않은 Rust 검사에는 `--locked --offline`을 사용했다.

수정 전 실패를 먼저 확인했다. 원래 저장 오류 처리에서 OS 오류 3이 출력됐는데도 종료 코드가 0이어서 새 회귀 검사가 실패했다. 원래 감사로그 읽기도 실제 Rust 배타적 잠금 중 Windows 오류 33을 반환해 새 잠금 대기 검사가 실패했다. 두 검사는 수정 후 전체 병렬 실행에서 통과했다. 다만 최초 실측 단계의 서버 검사 두 건은 원래 읽기 오류를 보존하지 않았으므로, 그 두 실패의 원인을 사후에 오류 33으로 확정하지 않는다.

초기 출력 오류 검사 시도 한 번은 지원하지 않는 `get_columns` 호출 때문에 컴파일 단계에서 실패했다. 이 로그는 동작 재현 근거로 세지 않고 별도 보관했으며, 이후 원래 구현의 실패를 실제로 실행해 확인했다. 작은 셀 대조의 첫 release 시도는 샌드박스에서 첫 실행이 출력 없이 120초 제한에 걸렸고 완료 0회로 기록됐다. 프로세스 종료를 확인했고 실패 JSON·원시 로그를 보존했다. 정확한 정체 원인은 확정하지 않았다. 이후 현재 debug 실행 파일을 같은 사용자 권한으로 검증한 결과와 섞지 않는다.

처음 두 입력의 16회 대조는 통과했지만 리뷰에서 상위 개수 제한을 실제로 줄이는 입력이 없음을 발견했다. 세 번째 입력을 추가하고 `take` 누락, 잘못된 제한 수, 같은 길이의 잘못된 경계 선택 등 8가지 변조 결과를 거부하는 검사로 보강한 뒤 최종 24회를 실행했다. 중간 16회 성공 보고서도 보존했다. 로컬에 없는 `actionlint`·`cargo-deny`는 실행하지 않았으며 원격 검사 통과로 표현하지 않는다.

## 기존 실측과의 구분

200M 측정 당시 런타임 소스 SHA-256은 `8953d0d9017b96cbde9d2917f8d9499fcedadad3c82e5e3d920f6f784c027995`다. 이후 CSV 출력 오류 처리를 수정했으므로 현재 소스와 다르다. 기존 성능 JSON·검증 JSON·원시 로그 묶음은 수정하지 않았고 release 실행 파일도 이번 후속 작업으로 재빌드하지 않았다. 현재 debug 실행 파일의 해시와 최종 검증 소스 해시는 별도 근거 묶음에 기록했다.

이번 작은 입력 검사는 기존 200M 실행에서 출력하지 않았던 P2/P3/P4 전체 셀이나 pandas P7을 사후 검증한 것이 아니다. 200M 성능을 다시 측정하지 않았으며 현재 수정본의 성능 수치라고 주장하지 않는다. 수집 마커도 요청한 API의 선택·완료 증거이며 모든 내부 연산 노드가 스트리밍으로 실행됐다는 증거는 아니다. GPU 작업과 #127·#129의 보류 범위는 유지했다.

- [후속 검증 원시 근거](../benches/results/windows-cpu-followup-2026-10-06-evidence.zip): `validation-summary.json`, 성공·실패 로그, 24회와 중간 16회 입력·스크립트·프로세스 기록, CLI 6개 사례, 최초 timeout 기록을 포함한다. `manifest.json`으로 각 원본 파일과 최종 소스의 SHA-256을 확인할 수 있다.

저장소 루트 PowerShell에서 다음 명령으로 현재 코드를 검사한다. GNU Windows 설정은 이 PC의 실행 파일 크기 문제에 해당한다. 다른 환경에 그대로 필요한 조건은 아니다.

```powershell
$env:PYTHONIOENCODING = 'utf-8'
./.venv-bench/Scripts/python.exe -m pip install -r benches/requirements.txt
./.venv-bench/Scripts/python.exe -m unittest discover -s benches -p 'test_*.py' -v
$env:CARGO_PROFILE_DEV_DEBUG = '0'
cargo fmt --all -- --check
cargo clippy --locked --workspace --all-targets -j 8 -- -D warnings
cargo test --locked --workspace -j 8
./.venv-bench/Scripts/python.exe benches/verify_benchmark_semantics.py --xazz-exec target/debug/xazz-exec.exe --out target/benchmark-semantics.json
```

필수 24회는 입력·모드·단계 수에서 계산하며 하나라도 누락되면 실패한다. 이 재현에는 대용량 CSV나 LFS 다운로드가 필요하지 않다. 보고서의 절대경로는 실행 당시 근거로 보존했다. 새로운 결과는 별도 파일에 기록해 과거 실패를 덮어쓰지 않는다.
