# 검증 데이터 분할 정책 (#162)

기존 초안 PR #248을 이어서 구현한다. 학습에 쓰지 않은 데이터로 평가할 수 있도록
분할 기준과 희소 클래스 처리 규칙을 명확하게 정한다.

## 분할 규칙

- 층화 기준은 `target` 단일 컬럼이다. 그룹·다중 컬럼 층화는 이번 범위에서 제외한다.
  클래스 값은 유한한 정수여야 한다.
- 검증 행 수는 정확히 `floor(전체 행 수 × validation_split)`이다.
  각 클래스는 학습에 최소 1개를 남기며, 표본이 1개뿐인 클래스는 학습에만 넣는다.
  이 조건을 지킬 수 없는 검증 비율은 크기를 몰래 줄이지 않고 오류로 처리한다.
- 검증 자리가 충분하면 표본이 2개 이상인 각 클래스에 검증 표본을 최소 1개 배정한다.
  나머지는 전체 클래스 비율에 비해 가장 부족한 클래스부터 배정한다.
  검증 자리가 적으면 모든 클래스의 검증 포함을 보장하지 않으며 실제 개수를 보고한다.
- 기본값은 `split: "sequential"`로, 뒤쪽 행을 검증에 사용한다.
  `split: "random"`은 고정 시드로 섞는다. 학습·검증 집합은 겹치지 않고 모든 행을 포함한다.
- `time_column`은 순차 분할과 유한한 숫자형 컬럼에서만 허용한다.
  시간을 오름차순 정렬하고 뒤쪽을 검증에 사용한다. 같은 타임스탬프가 양쪽에 걸치면
  오류로 처리한다. 검증 시간이 학습 시간보다 엄격하게 뒤에 있도록 보장한다.
  시간 컬럼과 무작위·층화 옵션을 함께 쓰면 체커와 런타임이 거부한다.
- 특성의 평균·표준편차 및 타깃 결측값 대체 통계는 학습 행만으로 구한다.
  검증 데이터에는 학습에서 구한 통계를 적용한다.
- 학습 JSON의 `validation`에 분할 방식, 시간 컬럼, 요청 비율, 실제 행 수,
  층화한 경우 클래스별 행 수를 기록한다.

```xzz
v trained = dataset |> train(Model, target: "class_id", epochs: 10,
    validation_split: 0.2, split: "stratified")
```

시계열에서는 숫자형 타임스탬프에
`split: "sequential", time_column: "timestamp"`를 사용한다.
이동 구간 평가나 구간 사이 간격은 구현하지 않았다.
참조 Rust 내보내기는 기존 순차 분할만 지원하며 나머지 분할·시간 옵션은 명시적으로 거부한다.
내보내기 기능 동등성 작업인 #129는 보류한다.

## 1차 검증 — macOS CPU, 2026-10-04

- 전체 테스트 678개 통과, 실패·무시 0개. 포맷 검사와 엄격한 Clippy 검사 통과.
- 희소 클래스, 정확한 검증 크기, 재현성, 잘못된 클래스·정렬 순서,
  중복·결측 시간, 옵션 충돌, 검증 이상치가 학습 통계에 미치는 영향을 검사했다.
- 실제 CLI `run --json`에서 8개 행을 학습 4개·검증 4개로 나누고,
  두 클래스가 각 집합에 2개씩 들어가는 것을 확인했다.
- #167과 동일하게 SDK 26.5를 사용했다. GPU·ONNX 및 #163과의 결합 상태는 미검증이다.
  공통 의존성의 보안·라이선스 검사 실패는 #167 기록대로 남아 있다.

## 다른 기준으로 재검증한 결과

1차 검증 이후 분할 규칙 88,533건을 전수 검사했다. 행 수 1~7, 클래스 3종의
가능한 배치, 비율 9종, 분할 방식 3종을 조합해 용량 초과 거부·학습 클래스 유지·
행 누락과 중복·검증 크기를 확인했다. 모두 통과했다.

별도로 반환된 모델에서 검증 MSE를 직접 계산하자 Dropout 때문에 보고 손실과
달라지는 문제가 드러났다. 검증 시 Dropout을 끄도록 수정했다.
유효 범위를 벗어난 비율은 자동 보정하지 않고 거부한다. 시간 정렬은 원래 정수 타입을
보존하며 `2^53`보다 큰 인접 타임스탬프와 부호가 다른 0의 경계를 검사했다.
실행 오류가 CLI에서 성공으로 보고되던 공통 런타임 경로도 실패 반환으로 수정했다.

수정 후 전체 테스트 **683개**, Clippy·포맷 검사가 통과했다.
실제 CLI의 잘못된 비율·시간 옵션 거부도 확인했다. 중간 실행의 서버 모의 러너
시작 대기 테스트에는 간헐 실패가 있었으며, 최종 재실행 통과만으로 그 원인이
해결됐다고 보지는 않는다. 상세 근거는 #167의 2차 재검증 기록에 모았다.


## #163과 결합한 검증 — macOS CPU, 2026-10-05

분류 브랜치에서 이 분할 구현을 병합하고 학습·검증 행을 분류 평가까지 연결했다.
앞/뒤 연속 슬라이스를 가정하지 않는 세 분할의 실제 모델 오라클로 전처리 통계,
분류 손실·지표 및 회귀의 최종 MSE를 확인했다. 전체 워크스페이스 **705개 테스트**,
엄격한 Clippy와 포맷 검사가 통과했다.

이 결합에서는 f32로 정확히 표현할 수 없는 층화 라벨도 명시적으로 거부한다.
예를 들어 서로 다른 큰 정수가 동일한 클래스로 합쳐지지 않도록 원래 타입으로 왕복 비교한다.
상세한 독립 검증 기준과 CPU CLI 재현 방법은
[분류 학습과 평가 지표 문서](classification-metrics.md)의 결합 검증 절에 있다.
