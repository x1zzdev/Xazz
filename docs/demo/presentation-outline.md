# 2차 평가 발표 구성 — 10장 / 10분 (#154, #196)

발표+데모 **10분**, 질의응답 **5분**. 슬라이드는 10장, 6장에서 영상 시연으로 넘어간다.

> 슬라이드: [`pitch-deck.html`](pitch-deck.html) · [`pitch-deck.pptx`](pitch-deck.pptx) · [`pitch-deck.pdf`](pitch-deck.pdf)
> 대본: [`presentation-deck.md`](presentation-deck.md) · 데모: [`demo-scenario.md`](demo-scenario.md)
> 질의응답: [`qa-brief.md`](qa-brief.md) · 생성: `python3 scripts/make_pitch_deck.py`

## 시간 배분

| 장 | 화면 | 시간 | 누적 |
|---|---|---:|---:|
| 1 | 표지 — 실제 IDE 화면 | 0:15 | 0:15 |
| 2 | 문제 — 세 문장 + 근거 1개 | 0:45 | 1:00 |
| 3 | 언어 — 코드와 실행 출력 | 0:50 | 1:50 |
| 4 | 게이트 — 세 지점, 두 게이트 | 0:55 | 2:45 |
| 5 | 성능 — 차트와 메모리 | 0:40 | 3:25 |
| 6 | **영상 시연 (2분 41초)** | 2:45 | 6:10 |
| 7 | 증거 — 차단과 변조 탐지 | 1:05 | 7:15 |
| 8 | 쓰이는 자리 — 타겟 3줄 | 0:50 | 8:05 |
| 9 | 지금 / 다음 + 한계 | 0:40 | 8:45 |
| 10 | 마무리 | 0:20 | 9:05 |

합계는 9:05다. **1분 가까운 여유**를 남긴 이유는 (1) 영상 재생이 늦게 시작될 수 있고
(2) 7장 이후 설명이 길어지기 쉽기 때문이다. 6:10에 영상이 끝나는 것만 지키면 된다.

## 설계 원칙 (왜 이렇게 생겼나)

- **페이지마다 구조가 다르다.** 표지(제품), 문장형, 코드형, 도식형, 데이터형, 영상 큐시트,
  증거, 목록형, 상태표, 마무리. 같은 머리구조를 반복하면 템플릿으로 보인다.
- **배경은 하나.** 전부 흰색. 검은색은 터미널 패널 같은 '내용'에만 쓴다.
- **장식이 없다.** 세로 띠·카드·그림자·라운드 박스·이모지·장 번호를 쓰지 않는다.
- **색은 의미로만.** 빨강=차단/불일치, 초록=통과. 나머지는 흑백.
- **글자는 15px 이상.** 출처·조건은 문장 한 줄로. 세부 근거는 발표자 노트와 문서로.
- **증거는 제품의 산출물 그대로.** 코드·터미널·진단은 생성 시점에 실제 `xazz`를 실행해 넣는다.

## 1. 표지 (0:15)

- 왼쪽: 대회명, `Xazz`, 한 문장(“실행 전에 검사하고, 실행 후에 증명합니다”), 저장소.
- 오른쪽: 실제 Visual IDE 화면. **“이게 오늘 데모할 화면”**이라는 신호를 준다.

## 2. 문제 (0:45)

- 제목: “터지는 순간은 대개 이미 늦다”.
- 세 문장: 스키마 불일치 / 경계 복사 / 실행 근거 부재.
- 근거는 **하나만**: Python 저장소 210개 분석에서 결함의 15%는 정적 타입 검사로 막을 수
  있었다 (Khan et al., IEEE TSE 2021, 저자들이 하한이라고 명시).
- ⚠️ “42%가 타입 오류” 같은 확인되지 않은 통계 금지. 두 번째 통계도 넣지 않는다.

## 3. 언어 (0:50)

- 제목: “타입과 프라이버시를 코드에 쓴다”.
- 왼쪽: 실제 `fds_safe.xzz`의 3개 파이프라인(집계 · DP · 연령대 집계).
- 오른쪽: **그 파일을 실행한 실제 출력** 4줄(정책 통과 · DP · shape · 파이프라인 수).
- 전달점: “선언한 것이 결과에 그대로 남는다”.

## 4. 게이트 (0:55)

- 제목: “게이트는 라이브러리가 아니라 파이프라인의 연산이다”.
- 도식: `.xzz` → **검사**(스키마·타입·정책) → Typed IR → **실행**(Polars·DP·Burn) → 결과.
  박스가 아니라 세 지점과 두 개의 세로선으로 그린다.
- 아래: 실제 `xazz check` 진단(3행 24열, Did you mean).
- ⚠️ “모든 런타임 오류를 잡는다” 금지. 잡는 범위만 말한다.

## 5. 성능 (0:40)

- 제목: “세 규모 모두 pandas보다 빠르다”.
- 차트 + 큰 문장 하나: “409만 행에서 피크 메모리 405 MB, pandas는 635 MB”.
- 캡션: Windows 11 한 대, release 빌드, 3회 중앙값, 파이프라인 실행 시간만.
- 3.84→2.14의 이유는 질문이 오면 답한다(양쪽 다 메모리 대역에 묶임).

## 6. 영상 시연 (2:45)

- 슬라이드에 6개 장면과 타임코드. 이후 **녹화 영상**을 전체화면으로 재생한다.
- 영상은 무음·자막 포함. 발표자는 장면마다 한 문장만 얹는다(자막을 읽지 않는다).
- 대본·준비·실패 대응은 [`demo-scenario.md`](demo-scenario.md).

## 7. 증거 (0:55)

- 왼쪽: 실제 차단 리포트(`$ xazz run fds_blocked.xzz`, XZP001)를 검은 터미널 패널로.
  설명 문장에 신용정보법 제32조·개인정보 보호법 제24조를 넣는다.
- 오른쪽: 서버 판정 인용(`The chain breaks at record #15`). 번호는 캡처에서 자동으로 온다.
- 마지막 줄: **“탐지이지, 방지가 아니다. 전체 재작성은 외부 앵커가 필요하다.”**
- UI 스크린샷 대신 타입으로 쓰는 이유: 반씩 줄여 넣은 스크린샷은 읽히지 않는다.

## 8. 쓰이는 자리 (0:40)

- 제목: “먼저 쓰는 곳은, 규제는 엄격하고 플랫폼 팀은 없는 팀이다”.
- 세 줄: 금융·의료(식별자 차단) / 대용량 로그(전처리 비용) / MLOps(PR 게이트).
- 포지셔닝 두 문장: “검사기를 읽고 고칠 수 있어야 감사가 성립한다. 그래서 오픈소스다.”
- 마지막 줄: “사례 데이터는 합성이며, 도입한 기관은 없습니다.”

## 9. 지금 / 다음 (0:30)

- 세 열: 지금 동작 / 진행 중 / 계획. 항목은 `docs/ROADMAP.md` 표기 그대로.
- 하단 한 줄로 **알려진 한계**(burn-cuda 실기 미검증 · ONNX Windows GNU 미지원 ·
  벤치마크 단일 호스트). 먼저 말하는 편이 질문에서 유리하다.
- 버전·라이선스: v0.4.1 · 2026-10-23 · Apache-2.0.

## 10. 마무리 (0:15)

- 두 줄: “실행 전의 검사, 실행 후의 증명.”
- 저장소 + QR. 질문은 이 화면에서 받는다.
