# 금융 FDS 현장 사례 — 카드 이상거래 집계

금융기관의 FDS(이상거래탐지) 파이프라인을 재현한 `.xzz` 프로젝트다.
"이상거래 의심 거래를 뽑아 달라"는 현장 요청이 **어떻게 규제 위반이 되는지**, 그리고
같은 질문을 **어떻게 안전하게** 답하는지를 한 쌍으로 보여준다.

> ⚠️ 데이터는 고정 시드로 생성한 **합성 데이터**다. 실제 고객·거래 정보는 한 건도
> 포함하지 않는다. 이 사례는 "실무에서 쓰이는 형태"를 재현한 PoC이지, 실제 금융기관의
> 도입 사례가 아니다. 프레이밍은 [`docs/design/field-validation.md`](../../../docs/design/field-validation.md) 참고.

| 파일 | 내용 |
|---|---|
| `generate_txns.py` | `data/transactions.csv`: 20,000건 합성 카드 거래 (시드 42) |
| `fds_blocked.xzz` | 규제 위반 예제 — 실행 전에 차단된다 (XZP001~XZP004) |
| `fds_safe.xzz` | 같은 질문을 안전하게 답하는 예제 — 통과 |
| `xazz.policy.json` | 금융 정책 팩(자동 로드) — 신용정보법·전자금융거래법 맥락 |

## 실행

```bash
cd examples/field_cases/finance_fds
python3 generate_txns.py            # data/transactions.csv (시드 42)
xazz policy fds_blocked.xzz         # 위반 리포트
xazz policy fds_safe.xzz            # 통과 (exit 0)
xazz run    fds_blocked.xzz         # 차단 확인 (exit 1)
xazz run    fds_safe.xzz            # 실행 → 업종별/연령대별 집계
```

`load("data/...")` 와 `xazz.policy.json` 이 이 디렉터리 기준이므로 반드시 이
디렉터리에서 실행한다.

## 무엇을 보여주는가

**위반 예제(`fds_blocked.xzz`)** — "순진한 구현"이 실행 전에 막힌다:

| 규칙 | 위반 내용 | 근거 |
|---|---|---|
| XZP001 | 고객번호·카드번호가 결과로 그대로 나감 | 신용정보법 제32조 · 개인정보 보호법 제24조 |
| XZP002 | 개인별 거래금액이 행 단위로 노출 | 신용정보법 제33조 |
| XZP003 | 나이+성별+우편번호 결합 재식별 | 신용정보법 제40조의2 |
| XZP004 | 업종별 거래금액 집계에 DP 미적용 | 신용정보법 제40조의2 · 가명정보 가이드라인 |

**안전 예제(`fds_safe.xzz`)** — 개인을 특정할 수 있는 값 없이 같은 질문에 답한다:

- 업종별 거래 건수·이상거래 건수 (식별자 없이 `count`/`sum`)
- 업종별 평균 거래금액 + 차등 프라이버시 (`withDp`)
- 연령대별(`age_band`) 이상거래율 (나이를 일반화)

결과 예시(연령대별 이상거래 건수, 시드 42): 30대 44건, 20대 37건, 50·60대 각 35건.

## 이 사례가 시사하는 것

- **성능과 규제는 다른 축이다.** 전처리가 빨라도 개인정보가 새면 쓸 수 없다.
- Xazz는 그 둘을 **같은 파이프라인**에서 처리한다 — 컴파일된 전처리 + 실행 전 정책 게이트.
- 위반 리포트는 `source_ref`(법조항)까지 감사 로그에 체인된다.

## 한국어 요약

카드 이상거래 집계를 소재로, "순진한 구현은 왜 규제 위반인가"와 "같은 질문을 어떻게
안전하게 답하는가"를 대조하는 예제다. 합성 데이터만 쓰며 실제 기관 데이터는 없다.
`fds_blocked.xzz` 는 XZP001~XZP004로 실행 전에 차단되고, `fds_safe.xzz` 는 식별자
없이 업종·연령대 단위로 집계하고 민감 속성에는 차등 프라이버시를 건다.
