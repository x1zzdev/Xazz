# CPU 분류 학습과 평가 지표 (#163)

기존 초안 PR #249를 이어서 구현한다. 숫자형 정수 클래스와
`Dense(클래스 개수)` 출력층을 사용해 분류 모델을 학습한다.
보고서·예측 컬럼·체크포인트 메타데이터는 0부터 시작하지 않는 원래 클래스 값도 보존한다.
`Dense(1)`은 타깃 값이 정수여도 기존 회귀 동작을 유지한다.

## 입력과 손실 함수

- 클래스는 2~1024개이며 타깃은 유한한 정수여야 한다. 출력 폭은 클래스 개수와 같아야 한다.
- 문자열 클래스 인코딩은 구현하지 않았다.
- 마지막 `Dense`가 만든 로짓에 교차 엔트로피 손실을 적용한다.
  모델 선언 끝에 Softmax를 붙이지 않는다. 보고서와 AUC 계산 시 확률로 변환한다.
- 클래스별 손실 가중치는 이번 변경에서 동일하게 유지한다.
  macro 지표로 소수 클래스의 성능을 드러내되 학습 목적 함수를 자동으로 바꾸지는 않는다.
  별도 가중치 문법과 정규화 규칙은 후속 설계가 필요하다.
- 이 브랜치는 순차 검증 분할을 사용하며 전처리 통계는 학습 행만으로 구한다.
  층화·시간순 분할 구현은 #162에서 별도로 진행한다.

## 보고서와 스윕

학습 보고서의 `classification`, 선택적인 `validation_classification`,
정렬된 `class_labels`로 학습·검증 결과와 클래스 순서를 제공한다.

- 정확도, 클래스별 값을 동일 가중 평균한 macro 정밀도·재현율·F1을 계산한다.
  클래스별 분모가 0이면 해당 클래스의 점수는 0으로 처리한다.
- 혼동행렬은 실제 클래스를 행, 예측 클래스를 열로 하는 일차원 배열이다.
- 이진 ROC AUC는 정렬된 두 번째 클래스의 확률을 사용한다. 동점에는 평균 순위를 적용한다.
  다중 클래스이거나 평가 집합에 한 클래스만 있으면 `null`이다.
  예측 클래스 자체를 확률 대신 사용하지 않는다.
- 스윕은 `cross_entropy`를 최소화하거나 `accuracy`, `precision`, `recall`, `f1`, `auc`를
  최대화한다. 검증 집합이 있으면 검증 점수를 우선한다. 정의할 수 없는 검증 AUC로
  우승 모델을 고르려 하면 학습 점수로 대체하지 않고 오류를 낸다.
- 분류의 기본 선택 기준은 교차 엔트로피이다. 각 조합의 지표를 JSON에 남긴다.
  `xazz run --json`의 `training`에는 마지막 학습 보고서,
  `sweep`에는 마지막 스윕의 조합·지표·우승 결과가 들어간다.
- 참조 Rust 내보내기는 분류를 명시적으로 거부한다. #129의 기능 동등성 작업은 보류한다.

## 1차 검증 — macOS CPU, 2026-10-04

- 전체 테스트 682개 통과, 실패·무시 0개. 포맷 검사와 엄격한 Clippy 검사 통과.
- 혼동행렬·macro 수식·동점 AUC·누락 클래스·잘못된 값·안정적인 확률 변환을 검사했다.
- 이진·다중 클래스 CPU 학습과 예측, 원래 클래스 복원, 체크포인트 메타데이터,
  검증 JSON, 스윕 우승 선택을 확인했다.
- 검증에 한 클래스만 있는 AUC 선택은 오류로 처리되며,
  검증 이상치가 학습 평균에 영향을 주지 않는 것을 확인했다.
- 실제 CLI에서 8개 행, 학습률 2개, `metric: "f1"`로 실행해
  JSON과 원래 클래스 예측을 확인했다. 이 데이터의 정확도는 성능 보장 근거가 아니다.
- #167과 동일하게 SDK 26.5를 사용했다. GPU·ONNX는 검증하지 않았다.
  공통 의존성의 보안·라이선스 검사 실패도 해결된 것은 아니다.
- 이 브랜치는 현재 main 기준으로 별도 검증했다.
  #248 반영 후 겹치는 학습·분할 코드를 통합하고 다시 검사해야 한다.

## 다른 기준으로 재검증한 결과

AUC를 기존 순위 합과 다른 양성·음성 쌍 비교 방식으로 4,096건 대조했다.
macro 지표는 2~4개 클래스의 정답·예측 조합 72,353건을 직접 계수해 대조했다.
두 검사 모두 통과했다.

추가 검증에서 배치 크기 1의 타깃 차원 축소 오류, 분류 스윕의 명시적 회귀 지표
허용, 잘못된 비율의 자동 보정, 실행 오류의 성공 보고를 발견해 수정했다.
검증 중 Dropout을 끄고, 보고서의 최종 분류 손실은 반환 모델의 평가 출력으로
다시 계산한다. 학습 과정의 배치 평균과 최종 모델의 손실을 혼동하지 않는다.
반환 로짓을 사용한 별도의 교차 엔트로피 계산으로 일치 여부를 확인했다.

실제 CLI의 이진·다중 클래스, 배치 크기 1·3, Dropout, F1·교차 엔트로피 스윕
3개 시나리오에서 예측 행으로 지표를 재계산하고 우승 조합을 대조했다.
잘못된 입력은 패닉 대신 종료 코드 1과 `success:false`를 반환한다.

수정 후 전체 테스트 **688개**, Clippy·포맷 검사가 통과했다.
중간 실행에서는 서버 모의 러너 시작 대기 테스트의 간헐 실패가 있었다.
단독·전체 재실행은 통과했지만 그 원인은 확정하지 못했다.
상세 근거는 #167의 2차 재검증 기록에 모았다. GPU·ONNX·#162 결합 검증은 여전히 남아 있다.
