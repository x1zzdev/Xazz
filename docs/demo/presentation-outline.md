# 2차 평가 발표 슬라이드 개요 (#154)

심사 기준(작품발표·작품 데모·정보 전달력)에 맞춘 10장 안팎의 발표 뼈대다. 각 장은
"한 문장 메시지 → 보여줄 증거" 순서로 쓴다. 수치는 출처가 확인된 것만 싣고, 출처가
없는 수치는 표시된 조건을 채운 뒤에만 쓴다.

## 1. 문제 (2장)

1. **파이썬 AI 파이프라인의 세 가지 구조적 비용**
   - 메시지: 타입·널 오류는 학습 도중 런타임에 터지고, 언어 경계마다 메모리가 복사되며,
     파이프라인 안에 보안·프라이버시 계층이 없다.
   - 증거: `README_kr.md` "왜 Xazz인가?" 표.
2. **거버넌스는 commodity가 되지 않는다**
   - 메시지: 엔진(하드웨어·커널)은 평준화되지만 "무엇이 실행됐고, 어떤 정책 아래 있었고,
     기록이 바뀌지 않았는가"는 여전히 비어 있다.
   - 증거: `README_kr.md` 도입부의 위치 설명.

## 2. 비전 (2장)

3. **겉은 스크립트, 속은 컴파일러, 실행 전에는 가드레일**
   - 메시지: `.xzz` 하나로 CSV에서 학습된 모델까지 가고, 실행 전에 타입·정책을 검사한다.
   - 증거: `docs/figures/pipeline-flow-kr.svg`.
4. **성능**
   - 메시지: Polars 기반 전처리로 pandas보다 빠르다.
   - 증거: "pandas 대비 최대 3.84배"는 `docs/submission_visuals_plan.md` A1에만 있다.
     슬라이드에 넣기 전에 측정 환경·데이터셋 크기·측정 시점을 벤치마크 원자료와 함께 적는다.

## 3. 데모 (4장 + 라이브 5분)

5. **데모 흐름 한 장 요약**
   - 순서: 그래프↔코드 → 전체 실행 → 영수증 → 모니터 → 감사 체인 → 히스토리 → 계보 → 정책 차단 → 스키마 추론.
   - 대본: `docs/demo/demo-scenario.md`.
6. **정직한 상태 표시**
   - 메시지: 서버가 돌려주지 않은 값은 그리지 않는다. 프로세스 종료와 파이프라인 성공은 다른 축이다.
   - 증거: `ide_run_progress.png`(에폭 진행률 "제공되지 않음"), `docs/design/state-contract.md`.
7. **보안 스토리**
   - 메시지: 정책 팩은 테넌트별로 설치되고 이력에 남는다. 식별자 노출은 실행 전에 막히고,
     감사 체인은 한 글자 변조도 위치까지 짚는다.
   - 증거: `ide_policy_packs.png`, `ide_policy_block.png`, `ide_audit_tamper.png`.
8. **프라이버시와 계보**
   - 메시지: ε는 실행을 넘어 테넌트 원장에 누적되고, 집계 결과 컬럼은 원본 컬럼까지 추적된다.
   - 증거: `ide_dp_ledger.png`, `ide_lineage.png`.

라이브 데모가 막히면 `docs/assets/demo/xazz-demo-ko.webm`(자막 포함)으로 바로 전환한다.

## 4. 로드맵 (1장)

9. **Scale 로드맵의 현재 위치**
   - 완료: A1·A2·A4, B1, C1·C2·C3, D1·D2 일부.
   - 진행: B2 표준 라이브러리, B3 LSP, F 트랙(GenAI 거버넌스), v0.4 릴리스(#183).
   - 증거: `docs/ROADMAP.md`의 "✅ done" 표기를 그대로 옮긴다. 표기 없는 항목은 "진행"으로 둔다.

## 5. 커뮤니티 (1장)

10. **공개 개발 방식**
    - 메시지: 역할별 트래킹 이슈(#104 IDE·UX, #105 프라이버시·ML·백엔드, #106 가드레일·sLLM,
      #155 커뮤니티 트랙) 아래 작업을 공개 이슈로 쪼개고, good first issue로 외부 기여 입구를 연다.
    - 증거: GitHub 이슈 목록, `CONTRIBUTING.md`, `docs/COMMUNITY.md`(Track G 계획).
    - 발표 직전 확인: Discussions(#156) 개설 여부, 외부 기여 PR 수.
